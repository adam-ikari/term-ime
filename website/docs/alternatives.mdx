# 为什么需要 term-ime

## 痛点

SSH 进远程 Linux 服务器，想写句中文 commit、改个中文配置——发现没有输入法。fcitx / ibus 要桌面、要 D-Bus，纯 TTY 跑不起来。常见 workaround 是本地打好中文，再粘过去。

term-ime 把 librime 拼音装进一个 PTY 虚拟终端：SSH 进来敲 `ti`，在该会话里直接打中文，候选栏画在终端最后一行，不依赖任何图形栈。

## 对比

| 方案 | 需 X/Wayland | 需 D-Bus | 纯 SSH TTY 可用 | 安装 |
|---|---|---|---|---|
| fcitx5 / ibus | 是 | 是 | 否（需图形前端） | 框架 + 引擎 + 前端，多包 |
| 终端模拟器内置 IME | 否 | 否 | 否（绑定本地模拟器，远程会话拿不到） | 无 |
| zhcon / unicon | 否 | 否 | 是，但年代久远、维护停滞 | — |
| **term-ime** | **否** | **否** | **是** | 一行 `curl`，单文件静态二进制 |

差异的核心：fcitx/ibus 是**系统级**输入法框架，靠 D-Bus 把候选送到图形前端；term-ime 是**会话级**，在自己托管的 PTY 里就地渲染候选栏，所以哪里有终端哪里就能用——SSH、容器、单用户修复模式都行。

## 何时选 term-ime

- SSH 登录的无桌面服务器、容器、单用户修复模式
- WSL / 容器里调试中文路径、写中文日志
- 信创国产服务器（麒麟 / UOS / 方德）无桌面终端
