# 更新日志

版本号沿用仓库的 Git tag。逐条提交与二进制下载见 [GitHub Releases](https://github.com/adam-ikari/term-ime/releases)。

## v1.1.3

四处用户能直接感觉到的变化。

**粘贴不再丢字。** 一次键盘读入的字节现在整段交给 shell，不再逐字节写。逐字节写意味着每喂一个字节，就把"还没送出去的出站队列"重新搬运并重排一次，再多一次 pty 写调用：65536 字节的粘贴实测 65652 次写，现在 19 次（其中 16 次恰好 4095 字节 —— 内核 pty 的单写上限，不是策略选择）。

**缓冲写满时丢最新，不再丢最旧。** 丢最旧会把一段文本从中间剪断：送出去的前半和后半接不上。丢最新保证送达的部分是原文的连续前缀，日志里另外写明丢掉了多少。能送多少由 shell 那侧是否在读决定，队列只保证顺序。

**字符集转义不再上屏。** 程序（htop、vim 等）发出的 `ESC ( B` 这类选择字符集转义，终止字符此前会被当成一次按键回显到屏幕；解析器现在进 SCS 子态等完整序列收完。

**日志。**
- 配置里写的 `log_file` 现在真的承载"配置加载"这件事的诊断。以前配置解析失败的报错落在启动日志，而用户打开的是配置指定的那个文件，两边看不到对方。
- 写不进配置指定的文件时继续写启动日志，并把仍在写哪个文件说清楚。以前这一步会把级别设成 off，于是这次失败之后的所有 warn/error 一起消失。
- warn 及以上立即落盘，其余最多等一秒。以前只在干净退出时 flush，被信号或关掉终端打断时，丢掉的正好是要看的那几行。

另外两项：终端尺寸越界不再回绕成另一个合法值（比如悄悄变成 65535 行）；pty / stdin / 信号的监听注册被拒时明确报错退出，不再留下一屏"像卡住了"的画面。
